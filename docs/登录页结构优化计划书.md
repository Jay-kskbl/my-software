## 0. 结论

登录页现在能用，但结构上有三类问题：

1. **会话处理有两处缺陷。** 后端暂时连不上时，刷新页面会删掉本地令牌，等于把用户强制退出；令牌过期后被送回登录页，重新登录后回不到原来的页面。
2. **逻辑全写在 `LoginView.vue` 里，没法自动测试。** 表单规则、先注册再登录的流程、跳转地址校验、错误显示都在同一个页面组件中。项目没有组件测试工具，所以登录页目前没有一项自动化测试。
3. **界面细节。** 出错时只在顶部弹一个约 3 秒就消失的提示；英文界面下后端返回的错误仍是中文；手机宽度下，右下角的“语言 / 配色”按钮挡住了“没有账号？注册”。

计划分 8 个任务（L1–L8）：先把逻辑抽成纯函数并补测试，再修会话缺陷，然后拆组件、改错误显示和布局。每个任务单独提交。

### 1.2 现在的登录流程

```
打开任意页面 → 路由守卫 → restoreSession()（只在第一次）
    本地有令牌 → GET /api/auth/me ─ 成功：已登录
                                  └ 任何失败（401、502、网络断开）：删掉令牌，当作未登录        ← A1
未登录且页面需要登录 → /login?redirect=原地址
LoginView.onSubmit → [注册模式] POST /register → POST /login → GET /me → 跳到 redirect
                    任何异常 → ElMessage.error（顶部提示，约 3 秒消失）                         ← C1
使用中令牌过期 → 任一请求 401 UNAUTHENTICATED → logout() → /login（不带 redirect）             ← A2
```

## 3. 目标结构

只改前端。`src/auth.ts` 保留原路径（`router.ts`、`App.vue`、`main.ts` 和各页面都引用它），新增一个登录目录放可以测试的逻辑：

```
frontend/src/
├── auth.ts                     会话状态（保留原路径）：restoreSession 区分“令牌失效”和“连不上”
├── features/login/             新增
│   ├── redirect.ts             纯函数：safeRedirect(raw)、loginRoute(fullPath)
│   ├── rules.ts                登录 / 注册两套表单规则（从 LoginView 移出）
│   ├── errors.ts               错误码 → 当前语言的文字；未知错误码显示后端原文
│   ├── submit.ts               提交流程：注入 register / login，返回“成功 / 失败 / 已注册但登录失败”
│   ├── LoginBrand.vue          logo + 标题 + 说明；logo 用插槽，不传时显示静态图标
│   └── LoginForm.vue           表单、模式切换、页内错误区（role="alert"）
└── views/LoginView.vue         只负责布局和组装（目标 60 行以内）
```

原则与 search-motion 一致：逻辑写成纯 TypeScript，用现有的 vitest 就能测；`.vue` 文件只负责显示和转发事件。这样不需要安装组件测试工具。

## 4. 任务

按编号顺序执行。每个任务完成后单独提交，提交前在 `frontend/` 下跑 `npm run typecheck`、`npm test`、`npm run build`。

### L1 抽出纯函数并补测试（行为不变）

- **改动：** 新增 `features/login/redirect.ts`、`rules.ts`、`errors.ts`（这一步只放现有行为：直接返回后端文字）；`LoginView.vue` 改为引用它们
- **跳转地址规则：** `safeRedirect` 只接受以单个 `/` 开头的站内路径；含反斜杠、控制字符，以 `//` 开头，带协议的，以及空值、数组参数，一律回落到 `/`
- **测试：** 新增 `tests/login/redirect.test.ts`、`rules.test.ts`。覆盖 `/search?q=1`、`//evil.com`、`/\evil.com`、`https://…`、空值、数组参数、`/login` 本身；注册规则的边界（用户名 2 / 3 / 32 / 33 个字符、非法字符，密码 7 / 8 / 128 / 129 位）
- **验收：** 页面行为与现在一致；新增测试全部通过

### L2 后端连不上时保留令牌（修 A1）

- **改动：** `auth.ts` 的 `restoreSession` 只在收到 401 时删除令牌；网络错误和 502 / 503 / 504 时保留令牌，`ready` 保持 `false`（下次导航时再确认），并对外提供 `auth.unreachable`
- **路由守卫：** 连不上时，需要登录的页面仍然跳登录页（带 `redirect`）；登录页显示“无法连接服务器，登录状态已保留”和“重试”按钮，点重试重新确认
- **测试：** 新增 `tests/auth.test.ts`，沿用 `client.test.ts` 的假 `fetch` 写法：401 → 令牌删除；网络错误、502、503 → 令牌保留；服务恢复后再次确认 → 已登录
- **风险：** 后端长时间不在时令牌一直留在本机。令牌本身 1 小时后过期，下次连上时会被 401 清掉，可以接受

### L3 令牌失效后回到原页面（修 A2、A4）

- **改动：** `main.ts` 的失效回调改为跳到 `loginRoute(当前地址)`；路由守卫里，已登录时访问登录页按 `safeRedirect(query.redirect)` 跳转
- **测试：** `loginRoute` 的单元测试：`/` 不带 `redirect`；`/search?q=合同` 原样带上；已在登录页时不重复叠加
- **验收：** 用模拟后端返回 401，在浏览器里检查一次（见第 5 节）

### L4 拆分组件（行为不变）

- **改动：** 新增 `LoginBrand.vue`、`LoginForm.vue`，`LoginView.vue` 只留布局；卡片标题改为 `h2`（修 C4）
- **logo（修 B3）：** `LoginBrand` 的 logo 用插槽，登录页传入 `StardustLogo`；不传时显示侧栏同款静态图标。以后合回主仓库时，去掉一行就不再依赖动效代码
- **验收：** 拆分前后截图对比，除标题字号外看不出差别；类型检查、测试、构建通过

### L5 提交流程与“已注册但登录失败”（修 A3）

- **改动：** 新增 `submit.ts`：`submit(mode, form, { register, login })` 返回三种结果之一：成功、失败（带错误）、已注册但登录失败（带错误）。最后一种情况下表单切回登录模式，保留用户名和密码，提示“账号已创建，请再点一次登录”
- **测试：** `tests/login/submit.test.ts`：登录成功；密码错误；注册后登录成功；注册返回 409；注册成功但登录失败；提交过程中重复点击只发一次请求

### L6 页内错误区，按错误码翻译（修 C1、C2）

- **改动：** `LoginForm.vue` 在按钮上方加错误区（`role="alert"`），错误一直显示到用户修改输入或重新提交。`errors.ts` 把 `INVALID_CREDENTIALS`、`USERNAME_TAKEN`、`VALIDATION_ERROR`、`NETWORK`、`UNAVAILABLE`、`DATABASE_UNAVAILABLE` 映射到 `i18n/messages.ts` 新增的 `login.errors.*`（中英文各一套），未知错误码显示后端原文。“注册成功”仍用顶部提示
- **测试：** `errors.test.ts`：每个错误码中英文各一条、未知错误码回落到后端原文、非 `ApiError` 的异常。`i18n.test.ts` 已有的中英文结构一致检查会自动覆盖新增文字
- **范围：** 只改登录页；文件页、预览页的顶部提示不动

### L7 布局：不被浮动按钮遮挡（修 C3）

- **改动：** `LoginView.vue` 在窄屏（≤ 600 px）时底部多留出浮动按钮的高度（约 72 px），让注册链接落在按钮上方；不改 `App.vue` 的浮动按钮
- **验收（浏览器实测）：** 375×600、375×812、768×1024、1280×720 四种尺寸下，用 `document.elementFromPoint` 检查注册链接中心点取到的是链接本身

### L8（可选，由 Barry 决定）登录页显示服务状态（修 C5）

- **做法：** 打开登录页时调一次公开接口 `GET /health`；后端连不上或数据库不可用时，在卡片上方显示一行提示和“重试”按钮；不轮询
- **理由：** 演示前一眼就能看出后端没启动
- **代价：** 多一次请求。`/health` 只返回状态，不暴露主机和端口（T24b 已处理）
- **不做的话：** L6 的页内错误区在点“登录”后也能给出清楚的原因
